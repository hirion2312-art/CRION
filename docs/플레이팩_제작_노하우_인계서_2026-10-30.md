## 3. CRION 구조 핵심 (플레이팩 만들 때 꼭 알아야 할 것)

### 3.1 층
- 본체(껍데기) `src/main.js`·`src/preload-host.js` → 바꾸면 새 설치 파일. **손대지 말고 히리온에게 먼저 말한다.**
- 화면 엔진 `src/renderer/*` → `engine.json` version 올려 push → 앱이 받아 다음 재시작에 적용.
- 팩 `packs/<id>/` → push 하면 `scripts/make-registry.js`가 레지스트리(index.json)에 싣는다. **팩에는 코드가 없다**(자료·그림·음악). 실행 코드는 엔진의 runner.

### 3.2 실행기(runner) 계약 — `app.js startPack()`이 넘기는 `o`
```
o.el  o.pack  o.files(.has/.url/.json)  o.manifest  o.data  o.work
o.send(text)        크랙 입력칸에 넣고 전송 한 번 (사용자가 누른 한 번 = 한 번)
o.action('regen')   다시 생성
o.click(id)         crack:state 의 actions[id] 버튼 누르기
o.load(url)         크랙 화면 주소 열기 (열기 전 gate=true → 새 문서 dom-ready 전 신호 무시)
o.workUrl           works.json 주소(공유 링크)
o.detailUrl()       공유 링크를 푼 뒤 처음 본 '작품 화면' 주소 (crion.detail.<workId>)
o.phone()  o.menu(extra)  o.rescan()  o.toast  o.copy  o.openExternal
o.showCrack()  o.showPack()  o.diag()  o.packOff()
```
실행기가 돌려줄 것: `onIpc(ch, d)`, `destroy()`, `demo(segs)`, `state`, `memory`, `saves()` (+ 마법소녀는 `proState()`), app이 `window.__pk`로 걸어 둔다(시험이 씀).

### 3.3 IPC (crack-preload → 앱 → 실행기)
- `crion:reply {key, segs, done}` — 응답. `segs`: `{t:'text', s, code}` / `{t:'img', src, w, h, alt}`. 크랙 화면에서 읽은 글이라 `*`, `**`가 이미 사라져 있을 수 있다(원문 그대로일 수도). 코드 상자 = `code:true`.
- `crion:state {page:'detail'|'chat'|'other', actions:[{id,kind:'new'|'mode'|'confirm',label,hidden}], url, msgs, users, input}`
- `crion:url {url, chat}` / `crion:sent {ok, why}`
- 새 대화 연결(`bindNew`)·시작 설정 고르기(`startModeStep`)·세이브(`saves`, `crion.pk.<id>.saves.<work>`)는 **리온대/마법소녀 실행기에 같은 코드가 있다. 새 팩은 그대로 복사**한다. 여기서 버그가 가장 많이 났다(8장).

### 3.4 manifest 칸 (자주 쓰는 것)
`runner`, `workId`, `workName`, `workUrl`, `adult`, `devOnly`(개발자 로그인 때만 스토어), `soon`/`soonNote`(보이되 플레이 막음·사전 다운로드), `startModes`(크랙 '시작 설정' 이름 — 하나면 자동으로 누름), `cover`(16:9), `previews`, `ui`, `minEngine`, `coverVideo`.
- 성인 팩 판정: `isAdultPack(p) = p.adult || 연결된 작품이 adult`. 이름 부분일치로 판정하지 말 것(전연령 아카데미가 PLUS 작품 때문에 숨던 버그).

### 3.5 폰 공통 틀 (0.10~)
- 폰 세로(≤760px)+팩 화면이면 `#app.pkv`/`body.pkv` → CRION 머리줄 숨김. 팩의 ⋯ 단추가 `o.menu(extra)`를 연다(팩 항목 + 크랙 원래 화면·새로고침·작품 페이지·신고·나가기).
- 팩마다 **아래 탭**(무대 + 패널들). 입력 중엔 `.typing`으로 탭 숨김. 키보드 높이 `--kb`. 알림은 위쪽.
- 폰에서 패널 탭을 열면 패널이 화면 전체를 덮고, **입력 버튼(채우기)을 누르면 무대로 먼저 돌아간 뒤 입력칸에 포커스**(숨겨진 입력칸은 포커스가 안 된다 — 8장).

### 5.2 해석 규칙 (pk-maou.js)
- **상태창**: 마지막 `🕖 D+n` 줄부터 코드 상자 끝까지. `🕖 D+n | 🏚️ 장소` / `👤 이름 상태 | 종족 (컨디션)` / `💫 권능 n/5 | 🔮 마력 n/50` / `💰 자금 n원`(만원 표기도) / `❣️ 호감도 (잠김)` 또는 `이름 n · 이름 n` / `💀 균열도` 같은 꼴 / `⚠️ 정체발각위험 n (라벨)` / `🏛️ 협회 동향` / `🤝 관계 | 이름: 태그`. 잠김이면 `null` → 기억에서는 **이전 값 유지**.
- `[오답노트]`(사칭금지 결과)와 스마트폰 화면 줄은 장면에서 뺀다. `[단서n] 시점 - 요약` → 단서 노트.
- **그림 = 등록명으로 해석**: CDN 주소 마지막 칸(24자리 id)을 등록명에 대응(`ImgIndex`). `_next/image?url=` 꼴도 포함 검색. 등록명 규칙: `감정_이름` / `기본상태_변신_이름` / `권능회수_사랑|전투|흑화_변신_이름` / `장소이름_장소` / `인물 외_타이틀`·`인물 외_프롤로그 웹툰 n` / `엔딩_엔딩명`.
- 그림 붙이기: 장소 그림 → 배경, 인물 그림 → 그 사람 대사에 (화자 이름과 같은 그림 우선). 묘사 줄에 붙은 인물 그림은 3마디 안에 그 사람이 말하면 그 대사에도.
- `권능회수_<방식>_…_<이름>` 그림이 나오면 **그 사람의 권능을 그 방식으로 되찾은 것**으로 기록(왕관 보석 색).
- `absorb()`가 남기는 것: 호감도/균열 변화(단계 변화 포함), 회수, 새 단서, 위험, 날, 자금, 엔딩, **관계 추이 `hist`(값이 바뀔 때만 한 점)**, **하루 기록 `days[D]`(장소·만난 사람·바뀐 것·첫 묘사)**.
- 관계 단계(원문 '핵심 시스템'): 0~19 적대·경계 / 20~39 무관심·거리두기 / 40~59 호의·친근 / 60~79 신뢰 / 80~100 깊은 유대.

### 5.3 화면 시스템 (이번 세션 최종)
- 디자인 개념 **「반지하 어전」**: 망명한 그림자 왕실이 반지하에서 여는 작전 회의. 낡은 금박(#c8a25a/#efd595)·봉랍 와인(#7a1f38)·벨벳(#1a1320)·잉크(#110c15). **별빛 색(#c4d6ff)은 오성(적)에게만.** 글꼴 Hahmlet(이름·날짜·제목·묘사) + Pretendard(본문).
- **그림자 왕관**(머리 왼쪽): 권능 5개 = 보석 5개, 방식별 색(사랑 #f08ab0 · 흑화 #9b6cff · 전투 #e2563f). 회수 순간 **의식 화면**(회수 그림 배경 + 큰 왕관 + 「군림」 + "왕관을 쓴다").
- **발각의 눈**: 위험 수치만큼 눈꺼풀이 열림(SVG). 70↑ 또는 '위기'면 무대 가장자리가 붉게 맥박.
- **D+n 카드**: 날이 바뀌면 가운데 크게 잠깐.
- 대사창: 벨벳 판 + 금박 두 줄 + 인물 색 **이름 깃발**(clip-path). 묘사는 Hahmlet, 대사는 Pretendard.
- 패널 탭: **오성**(표적 서류: 봉랍 도장=봉인, 관계 5칸 막대, 균열 금 간 막대, 추이 그래프, '이 장면에 있음') · **마왕군**(어전 회의 열기=/간부보고, 간부별 말 걸기·맡은 일 묻기) · **작전**(지금 할 일 — 위기/눈뜸/방송국 잠입/접점/권능 n개 단계별, 진행 단계, 명령 6종, 시간 건너뛰기, 단서 노트, 협회 동향, 엔딩 도감) · **일지**(하루 기록, 본 그림, 지난 대사).
- **입력 도우미**: 이 장면에 나온 사람에게 말 걸기 · 은신술(위험할 때) · 어전 회의(반지하) · 주변 살피기 · 사칭금지 칩, 「행동」 단추 = `*|*` 넣기(원문 사용자 입력 규격 `*행동* 대사`).
- '지금 할 일'은 **보이는 것만으로** 판단(방문한 장소, 권능 수, 위험). 숨은 진실 단계는 쓰지 않는다. "권능 3개째부터 갈래가 굳어짐", "전투는 3개 회수 뒤"는 원문 공개 규칙.

### 5.4 타이틀 (두 번 퇴짜 → 세 번째 통과)
- 1차: 흐린 배경 + 액자 속 그림 + 버튼 → "구려".
- 2차: 그림 전체화면 + 아래 띠 → 히리온이 새 그림(PC 가로 2040×950, 폰 세로 1080×1620) 주며 "풀화면, 비율 이쁘게, 글자가 버튼 가리지 않게".
- 2.5차: CSS로 cover 자르기 → **"이미지를 비율에 맞게 수정 못 하냐, 무지성 화면 자르기잖아"**.
- 3차(통과): **그림 자체를 다시 짰다.**
  - PC `title_pc.webp` 1920×1080: 원본에서 인물 영역(x 990~)만 잘라 높이에 맞춰 오른쪽에, 제목 글씨는 흰 바탕 위 검은 글자라 **밝기→알파로 떼어** 왼쪽 흰 여백 가운데에 다시 앉힘. 버튼은 제목 아래 흰 빈자리. 화면은 높이 맞춤 + 오른쪽 정렬, 더 넓으면 왼쪽 흰 바탕이 이어짐, 좁으면 오른쪽(인물 끝)부터 잘림 → 제목은 절대 안 잘림.
  - 폰 `title_m.webp` 1080×2340: 원본 그대로 + 아래로 원본 끝색(#020202) 바닥 연장 → 버튼은 MADE BY 아래 검정 바닥. 잘림 없음.
  - 버튼 위치는 그림 좌표 CSS 변수(`--x --y --w --h`, `container-type:size` + `cqw/cqh`)로 계산.
- 만든 스크립트: ZIP `tools/make_title_assets.py`.

### 5.5 프롤로그 연출 (웹툰 스크롤 → 누르면 다음)
- 히리온 웹툰 컷(1080×3000 세로 5장)에서 그림만 잘라 `assets/pro/` 12장(castle, gate, stars, girl, five, blue/red/green/purple/gold, city, room). 말풍선 상자는 그림에서 빼고 **문장을 자막으로 다시 조판**.
- 장면 종류(`data.json prologue.shots`): `card`(글자 한 장, tone light/dark/dusk, size big/mid) · `img`(액자 + 같은 그림 흐린 배경 + object-position/scale 천천히 이동, 같은 그림이 이어지면 액자 유지하고 움직임만) · `cast`(다섯 소녀 몽타주, 하나씩 섬광과 함께) · `seal`(왕관 보석 다섯이 흩어짐). 효과 `mqx-flash/quake/stars/glow/dim`, 효과음 글자 `sfx`.

- 크랙 프롤로그 응답(타이틀·웹툰 그림이 오는 응답)을 받으면 이 연출을 틀고, 끝나면 크랙 응답의 장면(반지하·세이렌)을 이어서 보여 준다.
- 컷 자르기 스크립트: ZIP `tools/crop_prologue.py`.

## 6. 디자인 노하우 (히리온 기준)

1. **주제에서 출발**: 작품 세계의 재료(반지하·왕실·봉인·방송국·별)에서 색·모양·이름을 뽑는다. 흔한 다크 판타지 카드 UI는 "기능만 있는 느낌"이 된다.
2. **기억에 남는 것 하나**: 마법소녀 팩은 '왕관 보석'과 '발각의 눈'. 나머지는 조용히.
3. **그림은 자르지 말고 다시 짠다**: 비율이 안 맞으면 PIL로 레이어를 나눠(인물/제목/배경) 목표 비율 캔버스에 다시 배치. 원본 끝색으로 캔버스를 늘리면 이음매가 안 보인다.
4. **글자와 버튼이 겹치지 않게**: 그림 속 빈자리(흰 여백·어두운 바닥)를 찾아 그림 좌표로 버튼을 놓는다.
5. **폰이 먼저**(이용자 대부분이 폰): 360·390·430 폭 모두 확인. 폰에서 패널은 전체 화면, 아래 탭, 입력 중 탭 숨김.
6. **연출은 누르면 넘어가게**: 스크롤 웹툰보다 장면 단위 + 천천히 움직이는 그림 + 타자 자막 + 효과 한두 개.
7. 글꼴은 Google Fonts에서 받되(`index.html` CSP가 fonts.googleapis/gstatic 허용), 시험 환경엔 없으니 9장 방법으로 확인.
8. 스토어·소식·사이트 그림은 **작품 실제 그림**으로. 자리 그림 스크린샷은 개발자 전용일 때만.
9. 히리온의 예전 기준(우사기 인수인계서): 앱 기본은 흰 바탕·고딕·깔끔, **게임 무대만 어둡게**. 팩 화면은 작품 분위기를 따른다.

## 11. 지켜야 할 규칙 (요약)

- 크랙 프롬프트·이미지·빌더 수정 금지. **원문 규격에 팩을 맞춘다.** 크랙 프롬프트 ↔ 팩 두 쪽 호환을 같이 본다.
- 숨은 진실·잠긴 값·'미정' 항목을 팩에 넣거나 지어내지 않는다.
- 자동 반복 전송 금지. 사용자가 누른 한 번 = 전송 한 번. 버튼은 입력칸에 **채우기만**.
- 본체(main.js·preload-host.js) 수정 금지 → 필요하면 멈추고 히리온에게.
- `config/works.json`·`config/thumbs/`는 히리온 것. 최신을 받아 **그 위에 추가만**(들여쓰기도 원본과 같게 — diff가 내 추가분만 나오는지 확인).
- 로그인 정보·service_role 키·비밀값 취급 금지. Suno 등 서비스 제한 우회 금지.
- 다른 팩은 히리온이 만들라고 할 때만.
