# CRION 인수인계서 — 우사기에게

작성: Claude (CRION 개발 담당) · 2026-10-25 · 기준 버전: 앱 본체 v0.3.0 / 화면 엔진 0.3.5

## 0. 우사기에게 주는 지시 (먼저 읽기)

너의 역할은 **CRION 검수자 겸 작업 지휘자**다. 직접 코드를 고치지 않고, 아래를 반복한다.

1. **검수한다** — 히리온이 보낸 사용 후기·스크린샷·진단 결과, 그리고 이 문서의 "검수 체크리스트(6장)"로 지금 버전의 부족한 점을 찾는다.
2. **우선순위를 정한다** — "백로그(5장)"와 새로 찾은 문제를 합쳐 순서를 매긴다. 기준: ① 잘못된 동작(오전송·엉뚱한 글 읽기) ② 플레이를 막는 문제 ③ 체감 품질 ④ 새 기능.
3. **Claude에게 지시한다** — "지시 형식(7장)"대로 한 번에 1~3개 작업을 준다. 작업마다 "완료 기준"을 꼭 적는다.
4. **결과를 확인한다** — Claude가 보고하면 완료 기준과 대조하고, 히리온에게 확인받을 것(실제 크랙에서의 동작)을 정리한다.

지켜야 할 것
- 크랙(뤼튼) 이용약관을 해칠 수 있는 기능(자동 반복 전송, 매크로, 대량 수집, 다른 사람 계정 정보 다루기)은 지시하지 않는다.
- 히리온의 결정이 필요한 것(돈이 드는 일, 공개 범위, 앱 본체 재배포, 데이터 삭제)은 Claude에게 바로 시키지 말고 히리온에게 먼저 묻는다. Claude도 이런 지시는 히리온에게 확인한 뒤 진행한다.
- Claude는 이 환경에서 **크랙 사이트에 직접 접속할 수 없다.** 실제 크랙 화면 확인은 히리온(또는 히리온의 컴퓨터)이 해야 한다. "실제 크랙에서 확인"이 필요한 작업은 히리온에게 받을 정보(화면 진단 복사 등)를 함께 적어 지시한다.

## 1. CRION이 무엇인가

- **히리온**(크랙 공식 크리에이터, 팔로워 약 4,000명)의 작품을 **채팅창이 아니라 게임 화면**으로 플레이하게 해 주는 **Windows·Mac 데스크톱 앱** (Electron).
- 대상: 히리온의 팔로워. 다른 크리에이터용 기능은 만들지 않는다.
- 원리: 앱 안에 크랙 웹페이지를 숨겨 띄우고, 크랙의 응답을 읽어 게임 화면(배경·대사창·상태창·선택지)으로 다시 그린다. 플레이어가 CRION 입력창에서 보내면 크랙 입력창에 넣고 크랙의 전송 버튼을 **한 번** 누른다.
- 디자인 방향(히리온 지정): 흰 바탕, 고딕, 깔끔. 어두운 판타지풍은 싫어함. 게임 무대 부분만 어둡게.

## 2. 구조와 주소

### 세 층
| 층 | 위치 | 바뀌면 |
|---|---|---|
| 앱 본체(껍데기) | `src/main.js`, `src/preload-host.js` | **새 설치 파일** 필요 (팔로워가 다시 설치) |
| 화면 엔진 | `src/renderer/*` | 앱이 자동으로 받아 **재시작 때 적용** |
| 작품 목록·공지·썸네일·음악 | `config/works.json`, `config/thumbs/`, `config/bgm/` | 앱이 30분 안에 자동 반영 |

### 화면 엔진 파일
- `crack-preload.js` — 크랙 페이지 안에서 동작. 채팅 화면인지 판단, 응답 읽기(보낸 뒤 새로 생긴 글자 추적 + 응답 칸 모양 학습), 입력·전송, 작품 소개 페이지의 '이어하기/새 대화' 버튼 찾기, 화면 진단.
- `crack-rules.js` — 크랙 화면 선택자(현재 비어 있음 = 모양으로 추측). 실제 크랙 구조를 알면 여기에 적는다.
- `catalog-extract.js` — 작가 프로필 페이지에서 작품 목록·썸네일 뽑기.
- `reply.js` — 응답 → 대사 장면·상태창·선택지 해석 (시험 15개).
- `store.js` — 작품별 내 기록(턴·시간·인물·앨범·명대사·단축 문장) (시험 7개).
- `app.js`, `app.css`, `index.html` — 화면 전체.

**홈**

- 작품 정보 창: 소개, 공략, 등장인물, 앨범, 명대사, 이어하기/처음부터

- 작품 목록: 작가 프로필에서 하루 한 번 자동 수집 + 관리 페이지 값 우선
- 공지 띠(관리 페이지에서 작성)

**플레이 화면**

- 입력줄: 보내기, 계속, 다시 생성, 지난 대화, 공략, 크랙 원본 화면, 단축 문장(작품별)
- 대사 별표(명대사 모으기), 몰입 모드(F), 작품별 배경 음악(관리 페이지에서 mp3 올리기)

## 5. 백로그 (우선순위 순, 우사기가 조정)

**A. 실제 크랙 검증 (가장 중요)**
1. 히리온에게 실제 플레이 후 '화면 진단 복사' 결과를 받아 `crack-rules.js`에 실제 선택자를 적기 (추측 대신 확정)
2. 작품 소개 페이지의 실제 버튼 이름 확인 (`crack-preload.js`의 START_WORDS)
3. '목록 진단 복사'로 작가 프로필 수집이 맞는지 확인 (`catalog-extract.js`)
4. 크랙 응답 속 그림의 실제 형태(alt·파일명에 인물 이름이 있는지) 확인 → 인물 그림 매칭 정확도

**B. 출시 준비** (자세한 내용: 프로젝트의 `CRION 정식 출시 기획안` 문서)
5. 오류 신고·건의 받는 곳 (디스코드 웹후크 또는 구글 시트 — 히리온 결정 필요)
6. 커뮤니티 연결 (디스코드/오픈채팅 — 히리온 결정 필요)
7. Mac 서명(Apple 개발자 연 99달러 — 히리온 결정), Windows 서명 여부
8. 업데이트 서명 켜기 (`npm run keygen` → GitHub Secrets)
9. 약관·개인정보 처리방침 페이지, 다운로드 페이지에 스크린샷
10. 다음 설치 파일 때 새 로고 아이콘 반영 (`build/icon.png`는 준비됨)

**C. 플레이 품질**
11. 공용 BGM(분위기별 8곡) — 히리온이 Suno로 제작, 문장 분위기로 자동 선택
12. 지난 대화 불러오기(크랙 기존 대화를 로그로)
13. 대사창 꾸미기 옵션(작품별 색), 이름표 색 자동
14. 상태창 해석 정확도 — 히리온 작품별 실제 상태창 예시로 `test/reply.test.js` 사례 추가
15. 스크린샷 저장·공유(장면 카드 이미지)

**D. 중단 상태 (히리온이 다시 하자고 할 때까지 하지 않음)**
- 작품별 전용 팩(전용 인터페이스). 기존 설계는 프로젝트 `크리온/00_인터페이스_제작_명령서.md`에 남아 있음.

- [ ] 설치: `CRION-Setup.exe` 실행 → 경고창 '추가 정보 → 실행' → 앱이 열리는가
- [ ] 첫 실행 안내 → 크랙 로그인 → 로그인 완료 → 작품 목록에 썸네일이 채워지는가

- [ ] 처음 한 번 보내기 → 응답이 대사창에 나오는가, **왼쪽 목록·메뉴 글씨가 섞이지 않는가**
- [ ] 응답 속 그림이 맞는 인물일 때만 보이는가
- [ ] 상태창이 옆 패널에 칩·게이지로 나오는가, ▲▼가 맞는가
- [ ] 선택지 버튼이 뜨고 누르면 한 번만 보내지는가
- [ ] 소개 페이지·댓글 칸에서는 절대 보내지지 않는가
- [ ] 앱을 다시 켰을 때 '이어하기'가 같은 대화방으로 바로 가는가
- [ ] 이상하면: 설정 → '화면 진단 복사' / '목록 진단 복사' 결과를 그대로 받기

## 7. Claude에게 지시하는 형식

한 번에 1~3개. 아래 틀을 그대로 쓰면 Claude가 바로 진행한다.

```
[크리온 작업 지시]
목표: (한 줄)
작업:
1. (무엇을 / 어느 화면·파일)
2. ...
완료 기준:
- (눈으로 확인할 수 있는 결과, 예: "가짜 크랙 화면 시험에서 세션 목록 글자가 응답에 0글자")
참고 자료: (히리온이 준 진단 결과·스크린샷 원문 그대로)
배포: 화면 엔진 업데이트로 / 설치 파일 필요 여부 확인 후 보고
```

Claude가 하는 방식(알아 두면 지시가 정확해진다)
- 저장소를 받아 `src/renderer`를 고치고 `engine.json` 버전을 올린 뒤 시험(`npm test`, `python3 test/ui/run.py`, `run_preload.py`, `run_detail.py`)을 통과시키고 main에 push, 배포 성공까지 확인한다.
- 앱 본체를 고쳐야 하면 멈추고 히리온에게 먼저 알린다.
- `config/works.json`(작품 목록)은 히리온이 관리 페이지로 고치므로 덮어쓰지 않는다.
- 크랙 실제 화면은 직접 볼 수 없으므로, 확정이 필요한 부분은 진단 결과를 요청한다.

## 8. 우사기의 첫 지시 예시 (그대로 써도 됨)

```
[크리온 작업 지시]
목표: 실제 크랙 화면 기준으로 인식 확정
작업:
1. 히리온이 보낸 '화면 진단 복사' 결과로 crack-rules.js에 입력창·전송 버튼·메시지 선택자를 적어라
2. 같은 결과의 마지막 메시지 구조를 test/ui/fakecrack.html에 반영해 가짜 크랙 화면을 실제와 같게 만들어라
완료 기준:
- run_preload.py 통과, 응답 글에 세션 목록·메뉴 글자 0
- 엔진 버전 올려 배포 성공
참고 자료: (진단 결과 원문)
배포: 화면 엔진 업데이트
```
