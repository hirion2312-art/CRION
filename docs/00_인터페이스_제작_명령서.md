# CRION 인터페이스 제작 명령서 v1

대상: 히리온 작품을 맡은 각 세션
목적: 이 작품을 크랙 채팅창이 아니라 **이 작품만의 게임 화면**으로 플레이하게 만든다.

---

## 0. 먼저 읽어라

너는 이 작품의 전문가다. 작품 문서(세계관, 시스템 프롬프트, 인물, 이미지 프롬프트, 상태창 형식)를 먼저 전부 읽고, 이 명령서대로 **CRION 인터페이스 세트**를 만들어라.

- 말한 범위만 작업한다. 작품의 기존 프롬프트·이미지·설정은 수정하지 않는다. 새 산출물만 만든다.
- 시작 전에 현재 상태부터 확인한다. 이미 있는 이미지·문서는 다시 만들지 말고 재활용한다.
- 작품 문서에 없는 사실은 지어내지 않는다. 필요한 제안은 "제안"이라고 표시한다.
- 모호하면 실행 전에 한 줄로 확인한다.
- 설계안(01)이 끝나면 요약해서 히리온에게 한 번 확인받는다. 이미지 양산은 그 뒤에 한다.

---

## 1. 원칙 (우선순위 순)

1. **작품의 색이 먼저다.** 모든 작품이 같은 대시보드로 보이면 실패다. 이 작품만의 소재(물건, 장소, 직업, 분위기)를 화면 자체로 만든다.
2. **채팅 앱처럼 보이면 실패다.** 말풍선 나열이 아니라 장면, 인물, 상태, 선택지가 화면에 놓여야 한다.
3. **이미지는 쓸 수 있는 곳에 전부 쓴다.** 배경, 입화, 표정, 이벤트 CG, 아이콘, UI 프레임, 지도, 도감, 타이틀, 엔딩까지 §6 목록을 빠짐없이 검토한다. 안 쓰는 항목은 이유를 적는다.
4. **정보는 글이 아니라 UI로 보여준다.** 작품의 모든 수치, 관계, 목록, 시간은 위젯에 배정한다. 글로 남기는 건 서사뿐이다.
5. **AI가 지킬 수 있는 만큼만 요구한다.** 표식은 짧고 단순하게. 표식이 깨져도 채팅으로 읽혀야 한다 (폴백).
6. **전송은 플레이어가 한다.** 선택지 버튼은 입력창에 글을 채우는 데까지만 한다. 자동 입력·전송·매크로는 금지.
7. **크랙 한도를 지킨다.** 메인 프롬프트 7000자, 키워드 노트 20개×400자, 전개 예시 500자, 이미지 분류표 80개·1600장.
8. **아래 부품 안에서 설계한다.** 없는 부품이 꼭 필요하면 §8로 요청한다. 규격을 임의로 바꾸지 않는다.

## 3. CRION이 그릴 수 있는 부품 (규격 v2)

### 화면 모드 (`mode`)

| 모드 | 모습 | 어울리는 작품 |
| --- | --- | --- |
| `vn` | 전체화면 배경 + 입화 + 하단 대사창 + 선택지 | 인물 중심, 연애, 모험 |
| `hud` | 큰 상태 패널 + 장면 이미지 + 작은 로그 | 운영, 시뮬레이션, 수집 |
| `hybrid` | 왼쪽 장면(배경+입화), 오른쪽 HUD, 아래 대사창 | 대부분의 작품 (권장 시작점) |
| `chat+` | 채팅 그대로, 배경·BGM·상태창만 입힘 | 채팅 비중이 압도적인 작품 |

### 부품

| 부품 | 설정 가능한 것 |
| --- | --- |
| `stage` 배경 | id, 전환(`fade` `cut` `slide`), 천천히 확대(`kenburns`) |
| `sprites` 입화 | 자리 `L` `C` `R`, 최대 3명, 인물.표정 id, 말하는 사람 강조 |
| `dialogue` 대사창 | 이름표, 프레임 이미지, 글자 속도, 서체, 글자색 |
| `choices` 선택지 | 0~4개, 버튼 스타일, 선택하면 입력창에 채움 |
| `hud` 위젯 | `tile`(큰 숫자) `gauge`(막대) `ring`(원형) `ratio`(n/m) `row`(목록) `mini`(작은 글자) `clock`(시계) `countdown`(D-n) `portrait`(인물 카드·호감도) `grid`(인벤토리) `map`(이미지+마커) `badge`(상태이상) |
| `log` 채팅 로그 | `hidden` `collapsed` `side` |
| `fx` 효과 | `shake` `flash` `vignette_red` `vignette_dark` `fog` `rain` `snow` `petals` `sparks` `dim` `heartbeat` `glitch` |
| `cg` 이벤트 일러스트 | 전체화면 표시, 닫기 방식 |
| `modal` 모달 | 도감, 인물록, 지도, 인벤토리, 업적 (이미지 + 목록) |
| `audio` | 장면 BGM, 효과음 id, 대사 중 BGM 낮추기 |
| `theme` | 색상(hex), 서체, 프레임·버튼·패널 이미지 |

서체 허용 목록: `Noto Sans KR` `Noto Serif KR` `Nanum Myeongjo` `Gowun Batang` `Black Han Sans` `Nanum Pen Script`

## 4. 01_화면설계.md에 반드시 담을 것

a. **화면 정체성 한 문장.** "이 작품의 플레이 화면은 ○○처럼 보인다."
   영감 예시(베끼지 말 것): 관리자 데스크의 CCTV 모니터, 마법 도감 서적, 길드 의뢰 게시판, 폰 메신저와 일기장, 재판 서류철, 무대 조명 뒤 대기실.
b. **모드 선택과 이유.**
c. **한 턴의 화면 흐름.** 응답이 도착해서 재생되고 선택지가 뜨기까지 순서.
d. **정보 배정표.** 작품의 모든 수치·상태·관계·시간을 위젯에 연결 (표).
e. **연출 지도.** 사건 → 배경, BGM, fx, 효과음, CG (표). 평상, 긴장, 위기, 해소, 이벤트를 모두 다룬다.
f. **테마.** 색 hex, 서체, 프레임 이미지 목록.
g. **화면 목록과 와이어.** 메인 플레이, 타이틀, 모달들. ASCII 도식으로.
h. **놓치기 쉬운 것과 위험.** 예: 표식이 자주 빠질 장면, 글자 수 압박.

## 5. 출력규칙 (AI 응답 표식, 규격 v2)

CRION은 응답 전체를 읽은 뒤 장면으로 재생한다. 표식은 화면에서 숨겨진다.

```
(서술은 표식 없이 그대로 쓴다)

【세라|웃음】"어서 와요, 관리자님."
【미나|걱정】"오늘은 식량이 좀 모자라요."

【장면|bg=식당_저녁|fx=dim|sfx=문열림】      ← 응답 중간에 장면이 바뀔 때만

【CRION】
bg=복도_밤
bgm=night
sprites=L:sera.smile,R:mina.worry
cg=
fx=
hud.food=82
hud.mor=64
choices=배급을 늘린다|배급을 줄인다|순찰을 나간다
【/CRION】
```

규칙:
- 대사 줄 앞에만 `【이름|표정】`. 표정은 생략 가능, 서술에는 붙이지 않는다.
- `【CRION】` 블록은 응답 **맨 끝에 한 번**. 이 응답의 기본 장면 + 다음 턴까지 유지될 상태 + 선택지.
- 블록이 없으면 직전 상태 유지.
- 값은 한 줄, 따옴표·줄바꿈 금지. 선택지는 `|`로 구분, 선택지 안에 `|` 금지.
- **id는 03_이미지_세트.md에 정의된 것만 쓴다.** 목록 밖 값은 쓰지 않고 빈칸으로 둔다.
- 상태창이 이미 정해진 형식의 글이면(예: 안전지대) `hud.*` 대신 기존 `status` 방식을 유지해도 된다.
- 폴백: 표식을 지우고 읽어도 이야기가 자연스러워야 한다.

### 02_출력규칙_프롬프트.txt 작성법
- 시스템 프롬프트에 넣는 문구는 **900자 이내**. "~한다" 같은 군더더기 어미와 접속어를 빼고 AI가 알아듣는 맥락 위주로 압축한다. 남는 글자는 작품 내용으로 쓴다.
- id 표(배경, 표정, 효과음, CG)는 길어지므로 **키워드 노트**(노트당 400자)로 분리하고, 노트를 어떤 키워드에 거는지 적는다.
- 전개 예시(500자 이내)에 표식이 들어간 평소 한 턴의 틀을 넣는다.
- 작품 고유 규칙(예: 큰 밤 날에는 반드시 특정 fx)은 문장으로 짧게.

## 6. 이미지 세트 (03_이미지_세트.md): 쓸 수 있는 건 다 쓴다

아래 A~J를 전부 검토하고, 만들 것과 안 만들 것(이유)을 구분해 적는다.

| 구분 | 내용 | 규격 | 파일명 |
| --- | --- | --- | --- |
| A 배경 | 장소 × 시간대(아침/낮/저녁/밤) × 상황(평상/위기) | 16:9, 1920×1080 | `bg_<id>.webp` |
| B 입화 | 인물 × 표정 × 의상. 표정은 기본 6종(기본·웃음·화남·슬픔·부끄러움·놀람) + 작품 고유 표정 | 세로, 무릎 위, 단색 배경 후 누끼 | `sp_<인물>_<표정>.png` |
| C 이벤트 CG | 첫 만남, 고백, 위기, 엔딩, 작품의 명장면 | 16:9 | `cg_<id>.webp` |
| D 아이콘 | 자원, 아이템, 스킬, 상태이상, 등급 | 256×256 | `ic_<id>.png` |
| E UI 부품 | 대사창 프레임, 이름표, 선택지 버튼, HUD 패널 프레임, 구분선, 게이지 틀, 모달 배경 | 작품 소재가 드러나는 질감 | `ui_<id>.png` |
| F 지도·도감 | 전체 지도, 지점 마커, 카드 프레임, 등급 엠블럼 | 지도 16:9 | `map_<id>.webp` |
| G 타이틀·로딩·엔딩 | 타이틀 화면, 로딩 일러스트, 엔딩 스틸, 앱 홈 작품 타일(4:3), 팩 아이콘(512×512) | 각 규격 | `ti_<id>.webp` |
| H 오버레이 질감 | 먼지, 빛줄기, 노이즈, 화면 테두리 | 투명이 어려우면 CSS로 대체 | `ov_<id>.png` |
| I (선택) 움직이는 배경 | 핵심 배경 2~3개를 클링 5초 루프로 | mp4/webm, 짧게 | `mv_<id>.webm` |
| J 크랙 분류표 연계 | 크랙 이미지 분류표용 이미지가 이미 있으면 id를 맞춰 **재활용** | - | - |

제작 규칙:
- 이미지 프롬프트는 **공통 화풍 태그를 각 프롬프트 안에 전부 포함**해서 블록 하나만 복사하면 되게 쓴다.
- 인물은 작품의 기존 외형·화풍 태그와 완전히 같게 유지한다. 새로 만들지 말고 기존 인물 이미지 프롬프트 문서를 먼저 찾아 재사용한다.
- **이미지 안에 글자·로고를 넣지 않는다.** 글자는 CRION이 위에 얹는다.
- 우선순위 3단계로 나눈다.
  - 1단계(플레이 가능한 최소): 핵심 배경 8장 내외, 주연 입화 × 기본 6표정, UI 5종, 팩 아이콘.
  - 2단계(풍성): 나머지 배경·입화, 아이콘, 이벤트 CG 핵심.
  - 3단계(풀 세트): 의상 변형, 도감·지도, 엔딩, 움직이는 배경.
- 팩 전체 용량은 webp 변환 기준 **150MB 이내**를 권장한다.
- 표 한 줄 형식: `id | 용도 | 크기 | 단계 | PixAI 프롬프트 | 파일명`

## 7. manifest.json (v2)

기존 v1 항목(`status`, `cycle`, `sceneRules`, `scenes`, `options`)은 그대로 유효하다. v2는 아래를 더한다.

```json
{
  "schemaVersion": 2,
  "id": "hirion.작품id",
  "name": "작품 이름",
  "version": "1.0.0",
  "mode": "hybrid",
  "identity": "화면 정체성 한 문장",
  "theme": {
    "accent": "#e8590c",
    "bg": "#101216",
    "text": "#f2f2f2",
    "fontBody": "Noto Sans KR",
    "fontTitle": "Noto Serif KR",
    "frames": { "dialogue": "assets/ui_dialogue.png", "hud": "assets/ui_hud.png", "button": "assets/ui_button.png" }
  },
  "assets": {
    "bg": { "식당_저녁": "assets/bg_식당_저녁.webp" },
    "sprites": { "sera": { "smile": "assets/sp_sera_smile.png" } },
    "cg": {},
    "icons": {},
    "sfx": {}
  },
  "hud": [
    { "widget": "tile", "key": "food", "label": "식량", "icon": "food", "pos": "right" }
  ],
  "log": "collapsed",
  "fxMap": { "bignight": ["vignette_red", "shake"] },
  "scenes": {},
  "status": {},
  "cycle": {}
}
```

- 모든 id는 §5 표식, §6 이미지 목록, manifest `assets`에서 **똑같은 글자**여야 한다.
- 파일 경로는 팩 폴더 기준 상대경로, `..` 금지.

## 8. 확장 요청

규격에 없는 연출·부품이 이 작품에 꼭 필요하면 `크리온/<작품명>/99_확장요청.md`에 적는다.

- 필요한 부품 / 이유 / 쓰일 장면 예시 / 규격 안에서의 대체안
- 규격을 임의로 바꾸거나 우회하지 않는다. CRION 개발 세션이 검토해서 규격 v2.x로 반영한다.

## 부록 v1.1 — 엔진이 추가로 읽는 manifest 칸 (모두 선택)
소환수 아카데미 작업에서 생긴 확장. 필요한 작품만 쓰면 됨. 모르는 칸은 앱이 무시한다.
- `status.fields[].type`: `number | ratio | text | list | blocks` — `list`는 `pattern/split/itemPattern`(이름 있는 그룹), `blocks`는 반복 블록(`start/end`, `max`, 하위 `fields`)
- `bgTime`: 시간대 접미사 규칙(저녁/밤/아침) · `bgAlias`: 장소 별칭
- `bgmByLoc`: 장소별 기본곡 · `bgmAlt`: 같은 필드 곡 번갈아 · `stage.bgmDefault`
- `seasonFx`: 계절별 기본 효과(꽃잎·눈·비 등)
- `battle`: `pattern`(이름 있는 그룹), `logPattern`, `skipLines` — 전투 패널
- `noticePattern`, `codePattern`: 도감·배지 알림, 🔑 코드 줄
- `cast`: 등장인물 이름 목록(`이름 "대사"` 읽기용)
- `minEngine`: 이 팩이 필요한 최소 엔진 버전
- 미지원: 영상 배경(`video`는 무시, 정지 이미지+켄 번즈로 대체)
